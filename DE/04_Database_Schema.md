# EventFlow — Data Engineering Documentation
## Deliverable 04: Physical Database Schema Specification & Data Dictionary

---

### 1. Schema Overview

The **EventFlow** database is implemented on **PostgreSQL (v14+)** within the `public` schema. All identifiers (table names and column names) are preserved in PascalCase and camelCase respectively via quoted identifiers as generated by **Prisma ORM 7**.

#### Summary Statistics:
- **Total Relations (Tables)**: 5 application entities (`User`, `Event`, `Registration`, `Attendance`, `Announcement`) + 1 migration tracking table (`_prisma_migrations`).
- **Custom Enumerated Types**: 3 (`Role`, `EventStatus`, `RegistrationStatus`).
- **Total Columns**: 51 database attributes.
- **Primary Keys**: 5 (all surrogate UUIDs of type `TEXT`).
- **Unique Indexes**: 4 non-PK unique constraints (`User_email_key`, `Registration_qrToken_key`, `Registration_studentId_eventId_key`, `Attendance_registrationId_key`).
- **Foreign Key Constraints**: 6 referential links.

### 2. Custom Enumerated Types (Enums)

PostgreSQL schema-level enums enforce domain integrity directly at the storage engine layer:

#### 2.1 `Role` Enum
Used to govern user authorization tiers:
```sql
CREATE TYPE "Role" AS ENUM ('STUDENT', 'ORGANIZER', 'ADMIN');
```
* `STUDENT`: Enrolled student eligible to browse campus events, register, receive digital tickets, and attend.
* `ORGANIZER`: Faculty coordinator or student club lead authorized to author, publish, manage, and verify events.
* `ADMIN`: University central administrator with platform-wide oversight, user directory access, and global metrics.

#### 2.2 `EventStatus` Enum
Tracks the multi-stage lifecycle of campus events:
```sql
CREATE TYPE "EventStatus" AS ENUM ('DRAFT', 'PUBLISHED', 'CANCELLED', 'COMPLETED');
```
* `DRAFT`: Newly created event undergoing review; hidden from public student event listings.
* `PUBLISHED`: Live and actively accepting student registrations until deadline or capacity.
* `CANCELLED`: Called off by organizer or administration; releases venue and halts bookings.
* `COMPLETED`: Successfully concluded; preserved for attendance audits and student activity records.

#### 2.3 `RegistrationStatus` Enum
Tracks participant enrollment state without deleting audit trails:
```sql
CREATE TYPE "RegistrationStatus" AS ENUM ('CONFIRMED', 'CANCELLED');
```
* `CONFIRMED`: Active seat reservation with a valid ticket QR pass.
* `CANCELLED`: Student voluntarily withdrew or was cancelled; frees up event capacity while preserving history.

### 5. Referential Integrity & Foreign Key Actions

| Constraint Symbol | Originating Table | Foreign Key Column | Referenced Table & Column | ON DELETE Action | ON UPDATE Action | Business Rule Justification |
| :--- | :--- | :--- | :--- | :--- | :--- | :--- |
| `Event_organizerId_fkey` | `Event` | `organizerId` | `User("id")` | **`RESTRICT`** | `CASCADE` | Prevents deleting an organizer account if active campus events belong to them. |
| `Registration_studentId_fkey` | `Registration` | `studentId` | `User("id")` | **`RESTRICT`** | `CASCADE` | Protects student attendance history; student accounts cannot be dropped while linked to tickets. |
| `Registration_eventId_fkey` | `Registration` | `eventId` | `Event("id")` | **`RESTRICT`** | `CASCADE` | Prevents deleting an event with confirmed student enrollments. |
| `Attendance_registrationId_fkey` | `Attendance` | `registrationId` | `Registration("id")` | **`CASCADE`** | `CASCADE` | If a registration record is purged, its venue attendance log cleans up automatically. |
| `Announcement_eventId_fkey` | `Announcement` | `eventId` | `Event("id")` | **`CASCADE`** | `CASCADE` | When an event is deleted, its broadcast announcements are automatically removed. |
| `Announcement_creatorId_fkey` | `Announcement` | `creatorId` | `User("id")` | **`RESTRICT`** | `CASCADE` | Prevents deleting a faculty author if their announcements remain on public notice boards. |
